# Maintenance plan

NextPulse is maintained in small, focused commits. One change a day.

This is a working plan, not a contract.

## Week 1

- Mon - unit tests for target parsing
- Tue - unit tests for fingerprinting
- Wed - security policy
- Thu - contributing guide
- Fri - continuous integration
- Sat - README pass
- Sun - issue and pull request templates

## Week 2

- Mon - Azure metadata parsing notes
- Tue - GCP metadata parsing notes
- Wed - Kubernetes metadata notes
- Thu - evasion header notes
- Fri - exit code table
- Sat - JSON output schema
- Sun - docs pass

## Week 3

- Mon - lab notes with an intentionally vulnerable Next.js app
- Tue - detection notes pass
- Wed - session export format
- Thu - performance notes pass
- Fri - troubleshooting guide
- Sat - references pass
- Sun - README pass

## Week 4

- Mon - release checklist
- Tue - verify the release notes
- Wed - tag the release
- Thu - final review
- Fri - sources check
- Sat - announce
- Sun - plan the next research item

## Commit conventions

- one change per commit, present tense
- subject under 72 characters, no trailing period
- run the checks before committing

## Daily checklist

1. Pick the next item.
2. Make the smallest change that completes it.
3. Run the checks.
4. Commit with a plain message.
5. Push to main.
